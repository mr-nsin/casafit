# CasaFit · api

ASP.NET Core Web API on .NET 10 LTS (C#), EF Core + Npgsql over Postgres, Redis for OTPs and rate limits, Hangfire for background jobs (not added yet).

See `docs/tech-stack.md` §2 and §3, `docs/architecture.md` §3 and the 2026-10-26 entry in `docs/decisions.md`.

> **Status.** The NestJS + Prisma scaffold is gone. Ported and working: `POST /v1/auth/code`, `POST /v1/auth/verify`, `GET /healthz`, `GET /openapi/v1.json`, the idempotency helper for form-check consume and refund, and the initial EF Core migration. Next: `/v1/me`, entitlements endpoints, refresh (plan tasks in `docs/plans/onboarding.md`). SMS and Play Integrity / App Attest are behind interfaces with dev fakes; no vendor is called.

## Layout

```
api/
  CasaFit.sln
  Directory.Build.props            nullable on, warnings as errors
  Directory.Packages.props         central NuGet versions
  Dockerfile  docker-compose.yml  .env.example
  openapi.json                     generated by the build; shared/ reads it
  src/
    CasaFit.Domain/                entities, no dependencies
    CasaFit.Application/           services, validators, idempotency, identifier normalisation
    CasaFit.Infrastructure/        EF Core + migrations, Redis, JWT, dev fakes for SMS and attestation
    CasaFit.Api/                   controllers, Program.cs, auth, rate limiting, OpenAPI
  tests/
    CasaFit.UnitTests/             xUnit + NSubstitute; runs shared/fixtures/identifiers.json
    CasaFit.IntegrationTests/      WebApplicationFactory + Testcontainers Postgres (needs Docker)
```

Each module (`Auth`, `Accounts`, `Entitlements`, `Content`, `Analytics`, `Admin`) is a feature folder in every project that needs it.

## Configuration

Environment variables only; see `.env.example` for the full list.

| Variable | Meaning |
|---|---|
| `ConnectionStrings__Default` | Postgres. Npgsql form or a `postgres://` URL |
| `Redis__Url` | `redis://` or `rediss://`. Empty means an in-memory store (single instance only) |
| `Jwt__Secret`, `Jwt__Issuer`, `Jwt__Audience`, `Jwt__AccessTtlSeconds`, `Jwt__RefreshTtlSeconds` | Token signing |
| `Auth__Pepper` | Server secret for hashing identifiers and codes |
| `Sms__Provider`, `Attestation__Provider` | `log` and `dev` are the only values so far |
| `Database__MigrateOnStartup` | `true` to apply migrations at boot |
| `PORT` | Honoured when set (Railway, Cloud Run) |

The process refuses to start in a non-Development environment if the secrets are shorter than the minimum or still start with `change-me`.

## Run locally

With Docker (api + Postgres 16 + Redis 7), from `api/`:

```bash
docker compose up --build
curl http://localhost:5080/healthz
curl -X POST http://localhost:5080/v1/auth/code -H "Content-Type: application/json" -d '{"phone":"9876543210"}'
```

The dev SMS sender logs the code with the number masked: `docker compose logs api`.

Without Docker for the api, with Postgres running on localhost:

```bash
cd api
dotnet restore
dotnet run --project src/CasaFit.Api        # Development: http://localhost:5080, migrates on start
dotnet test
```

Migrations (the `dotnet-ef` tool is a local tool, `dotnet tool restore` first):

```bash
dotnet dotnet-ef migrations add <Name> --project src/CasaFit.Infrastructure --startup-project src/CasaFit.Api --output-dir Persistence/Migrations
```

Building writes `api/openapi.json`. Commit it when the contract changes, then regenerate `shared/` types.

## Deploy to Railway

1. New project, deploy from this repo, root directory `api/`. Railway detects the `Dockerfile`.
2. Add the Postgres plugin and a Redis plugin (or Upstash). Reference them in variables: `ConnectionStrings__Default=${{Postgres.DATABASE_URL}}`, `Redis__Url=${{Redis.REDIS_URL}}`.
3. Set `Jwt__Secret`, `Auth__Pepper`, `Sms__Provider=log`, `Attestation__Provider=dev`, `Database__MigrateOnStartup=true`. Railway sets `PORT` itself.
4. Health check path: `/healthz`.

Railway regions do not include Mumbai. Use it for staging only; production data stays in India (see Cloud Run below).

## Deploy to Cloud Run (asia-south1)

```bash
gcloud run deploy casafit-api \
  --source api/ --region asia-south1 \
  --allow-unauthenticated --min-instances 1 \
  --set-secrets ConnectionStrings__Default=casafit-db:latest,Jwt__Secret=casafit-jwt:latest,Auth__Pepper=casafit-pepper:latest \
  --set-env-vars Sms__Provider=log,Attestation__Provider=dev,Database__MigrateOnStartup=true
```

- Cloud Run injects `PORT`; the app binds to it. The startup probe path is `/healthz`.
- `Redis__Url`: point at Upstash (`rediss://...`, Mumbai) or Memorystore through a VPC connector.
- Keep `--min-instances 1` once Hangfire is added. Run migrations from CI rather than `Database__MigrateOnStartup` when there is more than one instance.
- Do not ship `Sms__Provider=log` to real users: it prints OTP codes. Replace it with the DLT-registered vendor first.
