Login System & Multi-Device Sync

The OTP + JWT login system works in four steps:

Step 1
Send OTP
User submits phone or email. Server generates a 6-digit code with 5-minute TTL stored in Redis, sends via SMS (MSG91/2Factor.in).
Step 2
Verify Code
User enters code. Server verifies against Redis, creates or finds the account, returns JWT access + refresh tokens.
Step 3
Token Pair
Access token: 15 min, stateless JWT.
Refresh token: 30 days, stored per device in device_sessions.
Step 4
Offline Grace
7-day offline grace via cached session in SecureStore. 30-day refresh token ensures silent re-auth on reconnect.

Multi-Device Login

Each device gets its own independent token pair. A device_sessions table tracks all active sessions per account. Features:

  • Concurrent sessions: allow up to N devices (configurable, default 5)
  • Remote logout: user can revoke any device from Settings
  • Refresh rotation: each refresh token is single-use; replay detection revokes the entire family

Data Sync Across Devices

Pull-based sync (recommended for a workout app): each device calls GET /sync?since=<timestamp> on app open, and the server returns deltas.

  Video format: H.264 AVC / MP4 (max Indian device compat)

Recommendation

Use MP4 progressive download over HLS for 10–30s exercise demos. HLS adds complexity (manifest + segments) with no benefit for clips this short. Pre-generate 3 quality tiers at upload time.

Recommendation

Keep NestJS for now. The shared TypeScript with the React Native app, the official RevenueCat SDK, and the larger Indian developer pool outweigh .NET's performance advantage at CasaFit's current stage. Consider .NET only if the team has .NET expertise or performance bottlenecks emerge.

India Data Residency

Railway and Render have no India region — nearest is Singapore. This fails DPDP Act compliance for the API/database layer. For the API compute, use AWS App Runner (Mumbai) or Azure Container Apps (Central India). Cloudflare R2 stores video in the nearest APAC region, but its CDN caches in 22+ Indian cities.

Supabase as CasaFit's Backend?

Supabase Pro ($25/mo) bundles Postgres + Auth + Storage + Edge Functions + Realtime. It can replace the database and auth layers, but not the full backend: edge functions are limited to 256 MB RAM and 2s CPU, insufficient for complex business logic like plan generation or entitlement management. Use Supabase for data + auth, keep NestJS/.NET for API logic.

Final Recommendation

Start with permanent free tiers, not 12-month trials. AWS's free tier cliff is a budgeting trap for startups. Choose zero-egress storage early — CDN bandwidth will become the dominant cost for a video-heavy fitness app. The recommended hybrid stack: Supabase Pro (Mumbai) for the data layer, Cloudflare R2 for video assets, AWS App Runner or Azure Container Apps for compute, Upstash for serverless cache, MSG91/2Factor.in for SMS, FCM for push, RevenueCat for billing, PostHog + Sentry for observability.
